# OpenApi

本地整理 HTTP 接口的桌面应用。用 Rust 管数据和导入，用 Tauri 2 做成 macOS、Windows、Linux 都能打包的窗口。界面只做三层：系统、接口、用例。

## 系统

一个服务是一个系统，例如 `scm-po-service`。业务域（计划、供应链、采购等）只出现在左侧分组里，用来定位，不单独做页面。环境地址挂在服务上，因为每个服务有自己的发布页。

系统上可以记：

- 名称
- 业务域
- 一句说明。平时收成标题下的小备注，全文都显示；点一下才展开编辑，点外面收回去
- 环境：名称、发布页地址、请求主机、备注。主机用于「复制到 X」和用例标题行的环境标识
- 链接：名称、地址、备注。yapi、wiki 这类页面
- 变量：名称、值，可标记为密文。环境、链接和变量在顶栏「环境」弹出的配置框里，点空白处或「关闭」收起，不挤占接口列表。全局变量一直显示；点一个环境后，才列出这个环境自己的变量，同名时覆盖全局。用例里写 `{{name}}`，复制、运行，以及选中文字后直接复制，都会换成变量的值。密文在界面上打码

环境、链接、变量都是一行一条，悬停出现打开、复制、编辑、删除，拖动左边把手调顺序，编辑在行内展开。地址含 `environment?tab` 或 `env=` 的链接自动归为环境；环境没填主机时，会从该系统用例里出现过的主机给出建议。

从 Markdown 导入时，`paas`、`yapi`、`corp.100.me` 这类页面地址会收成链接。`env=` 参数作为名称，例如 `TE`、`EAST1GRAY`。接口请求本身的地址不放进链接。

## 接口

同一个系统里，按「方法 + 路径」合成一条接口。主机、查询参数、请求体不同，都不另开接口。

打不开路径的 curl 归到 `CURL /未解析`，原文仍保留。

接口可以收藏（星标排在前面，侧栏有「收藏」组）、写一行备注，记录最后修改时间。路径只差大小写或末尾斜杠的两条接口标「可合并」，点它把后一条的用例并进前一条。接口可以「移动到…」另一个系统。

## 用例

一个用例是一个独立的文本代码框，里面通常是一条完整 curl，也可以在上面写一句说明。同一个接口下纵向排多个框。正文里第一条以 `#` 开头的行会当作这个框的标题，没有则显示「用例 N」。复制出去的仍是全文。

每个框只操作自己：

- 复制这一个框的全文，`{{变量}}` 已替换
- 复制到 X：用那个环境的变量（覆盖同名全局变量），主机填了就换主机，不改原文
- 运行：每条 curl 左边有一个播放图标，只执行这一条，执行中变成停止。在本机 shell 执行，30 秒超时。结果显示退出码、耗时、大小，JSON 自动缩进，stderr 折叠
- 格式化 / 还原：一个参数一行、JSON 缩进；带管道或引号不配对的不动
- 显示结构：右侧展开方法、地址、查询参数、请求头、请求体 JSON
- 再写一条：复制成下一个框，再改参数
- 移动到…：挪到别的接口
- 删除这一个框

标题行显示环境名或主机、相对修改时间。选中文本 3 个字符以上会出现「设为变量」，把这段文字在整个系统里替换为 `{{name}}` 并新建变量。未定义的 `{{变量}}` 标红。

导入时不改写原文，框里的内容和文档里的 curl 一致。相同系统、相同方法路径、完全相同的文本不会重复插入。

## 界面

左侧按业务域列出系统，上面是「最近」和「收藏」两组，点组标题可以收起或展开，收起状态留在本机；搜索时全部展开。悬停业务域可以看到「改名」和「删除」，双击名称同样可以改名，这个域下的系统一起改。删除业务域后，里面的系统归到「其他」，系统本身不删。「其他」、最近和收藏不能删。可按系统名、路径、用例文本搜索，支持前缀 `post:`、`path:`、`sys:`、`#标题`。命中的路径完整显示，长路径换行不截断。搜索框里按 `↑↓` 在系统和接口之间移动，右侧同步切到那个系统并滚到那条接口；`Enter` 把焦点交给接口行，`Esc` 清空搜索。有关键字时，系统下面列出命中的接口，点一行就打开并滚到该接口；右侧只显示命中的接口。关键字清空后恢复完整列表，接口重新收起。只搜到系统名、没有接口命中时，右侧仍显示该系统的全部接口。

接口默认收起，点开才看到用例框。接口列表标题旁可以按 GET、POST 等方法筛选，右侧有「全部展开」「全部收起」。路径旁边有「复制」和「编辑」。编辑在弹框里改，保存后对得上的用例会把 curl 里的路径换成新的，主机和查询参数不动。路径本身不能用光标选中。接口标题行悬停出现「复制全部」「移动到…」，复制全部把该接口全部用例拼起来复制。`Command+K` 聚焦搜索框，`Command+P` 打开快速跳转：模糊匹配系统、接口、用例标题，记住最近 8 条。

接口行可以用键盘：`↑↓` 移动，`→` 展开，`←` 收起，`Enter` 切换，`Command+C` 复制全部。下次打开会回到上次选中的系统，侧栏最上面列出最近打开的 5 个。添加系统在左上角「+」里。名称已存在就直接打开；业务域可以选已有的，也可以输入新的，留空则按服务名前缀归类。删除系统在系统名右侧的「⋯」里，删除入口会先确认。

添加接口的输入框在接口列表上方，平时一行高，聚焦后撑开。粘贴一条 curl，应用解析出方法和路径：没有这条接口就新建，并带上这条用例；已经有了就跳到该接口，把这条 curl 加进用例。完全相同的用例不重复添加。

顶栏左边是「业务域 / 系统名」和接口数，右边是保存状态点（绿已保存、橙保存中、红失败）、导入、设置。操作提示在底部浮一下，2 秒后消失；失败提示常驻到下一次成功。

数据改动后自动写入本机 SQLite。`Ctrl+S` 或 `Command+S` 会立刻保存。

设置里可以选外观（跟随系统、浅色、深色）、curl 底色和字号、查看并打开数据目录、备份全部、从备份恢复。这些选择留在本机。浅色底会自动换成深色字。

系统名右侧「⋯」里有「导出为 Markdown」：一个系统一个文件，环境、链接、变量在前，接口按 `## 方法 路径`、用例按 `### 标题` 加 bash 代码块，密文变量写成 `***`。

原生菜单：文件（导入 Markdown、从 YApi 导入、保存、导出这个系统、备份全部、从备份恢复、打开数据目录）、编辑、视图（搜索、快速跳转、放大缩小 curl 字号、全部展开收起）、帮助（快捷键、关于）。

## 导入规则

选择一个目录后递归读取 Markdown。

- 跳过 `README.md`、`SERVICE_INDEX.md`、`DATA_INDEX.md`
- `services/服务名.md` 的系统名是文件名
- `services/服务名/主题.md` 的系统名是目录名，多篇文档并进同一个系统
- 目录外的 `集成测试请求.md` 用文件名当系统名

业务域按服务名前缀归类：`plan-` 计划，`scm-` 供应链，`ddmc-` 和 `greatwall` 采购，`risk-control` 风控，`sku-` 商品，`pms-` PMS，`abtest` 实验，`algo-` 算法。其余放到「其他」。文件名含「集成测试」时放到「集成测试」。

`ab` 压测命令会单独成一个用例框，框里是这一行命令。

## 从 YApi 导入

系统名右侧「⋯」里的「从 YApi 导入…」，或文件菜单里的「从 YApi 导入到这个系统…」。填 YApi 地址和项目 token（YApi 项目设置 → token 配置），地址会从该系统的 yapi 链接里预填，填过的留在本机。

应用用 token 调 YApi 的开放接口：`/api/project/get` 拿项目名、basepath 和环境；`/api/open/plugin/export-full?type=json` 拿全部接口，这个插件不可用时退回 `/api/interface/list_menu` 加逐条 `/api/interface/get`。

每条 YApi 接口生成一条 curl：第一行 `# 标题`，地址是「请求主机 + basepath + 路径」，查询参数带示例值，请求头照搬，JSON 请求体从 JSON Schema 生成示例（字符串空、数字 0、布尔 false、数组一项），form 用 `--form`。请求主机留空时用 YApi 项目环境里的第一个。

只新增，不覆盖：按「方法 + 路径」比对，本地已有的接口整条跳过；YApi 里同一路径的多条合进一条接口。分类名会写进这个系统的分组名单；本地已有接口不改 curl，还没分组的会补上分类名。项目环境里本地没有的会补进「环境」卡。

分组记在系统上，空分组也会留下。当前系统的分组直接排在侧栏该系统下面：点系统展开，再点一次收起；点分组只看这一组，末行「新建分组」或接口列表上的「新建分组」可以新建，分组行上可以改名或删除。侧栏右缘可以拖动改宽度。分组左侧的手柄可以拖动排序，侧栏和接口列表是同一份顺序。删除分组会把里面的接口移到未分组，接口还在。接口列表里每个分组标题上也有「改名」和「删除」，点标题收起。没有分组的系统仍是平铺列表。悬停接口行可以「分组」，选已有分组、未分组，或填一个新名字。正在看某个分组时，新贴的 curl 会进这个分组。

## 存储

手册存在本机 SQLite 文件 `library.db`。一次保存放在一个事务里，写到一半退出不会留下半截数据。标识符是 `dev.openapi.notebook`。

- macOS：`~/Library/Application Support/dev.openapi.notebook/library.db`
- Windows：`%APPDATA%\dev.openapi.notebook\library.db`
- Linux：`~/.local/share/dev.openapi.notebook/library.db`

如果目录里还有旧的 `library.json`，而且数据库是空的，第一次打开会把它导入数据库，并把原文件改名为 `library.json.imported`。

旧库打开时按列补齐表结构，`links.kind` 按地址回填。每次启动把全库写一份 JSON 到 `backups/library-<时间>.json`，保留最近 7 份。「备份全部」把同样的 JSON 存到指定位置；「从备份恢复」先备份当前数据再整库替换。

## 多平台

业务逻辑在 `src-tauri`，不依赖某个操作系统。窗口、打开链接、选择目录、写入剪贴板都用 Tauri 2 的插件，同一套代码打包到桌面三端。`src-tauri/src/lib.rs` 保留了 Tauri 的移动端入口，手机端以后可以在这套接口上继续加，不另写一套数据层。

## 代码布局

- `src-tauri/src/model.rs`：系统、链接、变量、接口、用例
- `src-tauri/src/store.rs`：用 SQLite 读写，表结构升级，自动备份与恢复
- `src-tauri/src/import.rs`：从 Markdown 抽出 curl、压测命令和链接
- `src-tauri/src/export.rs`：系统导出为 Markdown
- `src-tauri/src/yapi.rs`：调 YApi 开放接口，把接口定义转成 curl
- `src-tauri/src/run.rs`：在本机 shell 运行命令，可超时和停止
- `src/curl.ts`：curl 分词、格式化、结构解析、变量替换、主机替换、搜索匹配
- `src/main.ts`、`src/styles.css`、`index.html`：界面
